# 0002 · Astro for pages, raw Three.js for the globe

- Status: accepted
- Date: 2026-10-08

## Context
The product is a WebGL globe, which search engines and AI assistants cannot read. The site also
needs many indexable text pages (home, one page per detected storm, region pages, methodology).
The globe's value is its rendering: day/night blending with twilight bands, atmosphere, clouds lit
from inside by lightning, GPU-instanced flashes.

## Options
- **Astro + raw Three.js**: Astro renders HTML pages for crawlers and loads the globe as a deferred
  island; Three.js gives full control over shaders and render passes.
- **Astro + globe.gl**: faster start on a basic globe, but its abstractions sit between us and the
  custom shaders that are the core of the product; we would end up working around the library.
- **Vite single-page app + pages generated by the Python collector**: fewer tools, but we would
  reinvent templating, sitemaps, Open Graph tags and routing.

## Decision
Astro for every page and the SEO layer, with the globe written directly with Three.js and custom
shaders, loaded after the page's text content.

## Consequences
- Text content is visible immediately and indexable; the globe never blocks Core Web Vitals.
- More rendering code to write ourselves (camera controls, picking, layers), in exchange for full
  control of the visual result and of performance on mobile.
