# 0005 · Cloudflare Workers with prerendered pages and on-demand storm and region pages

- Status: proposed
- Date: 2026-10-08

## Context
Storm pages (`/storms/<slug>`, #88) and region pages (`/live/<country>`, #90) appear and change
continuously, as the pipeline on the VPS detects storms and writes JSON to the `scintille-live` R2
bucket. A storm must get a crawlable HTML page without a deploy (#88). Everything else (home,
methodology, legal) changes only with the code. The setup must stay free or near free, and the
domain is already on Cloudflare.

What current official sources say (see Sources):
- Cloudflare now tells new projects to start on Workers, its primary platform; Pages gets no new
  features first. Workers serves static assets for free and without limit, and only runs the Worker
  script for requests that do not match a file.
- Workers Free: 100,000 script requests per day, 10 ms CPU per request, hard errors past the limit.
  Workers Paid: 5 USD per month, 10 million requests and 30 million CPU ms included.
- Pages Free: 500 Git builds per month, 1 concurrent build. The docs do not say whether direct
  uploads count toward that cap. Workers Builds Free: 3,000 build minutes per month.
- `@astrojs/cloudflare` (v13+, required since Astro 6) only targets Workers. Pages stay prerendered
  by default; `export const prerender = false` renders one route on demand. Bindings, including
  R2, are imported from `cloudflare:workers`.
- Astro 7 route caching (`Astro.cache.set`, tags, invalidation) is stable, but its Cloudflare
  provider is still experimental. That provider turns on Workers Cache, and with Workers Cache on,
  static asset requests count as Worker requests.

## Options
- **Astro static + on-demand routes on Workers, reading R2 through a binding.** A page exists as
  soon as its JSON is in R2. No build quota is involved, and crawlers get plain HTML. Costs: a
  runtime on the request path, the 10 ms CPU and 100k requests/day caps on dynamic routes, and
  caching to design.
- **Same, on Pages Functions.** The current Astro adapter no longer supports Pages, and Cloudflare
  points new projects to Workers. Rejected.
- **Fully static, rebuilt a few times a day by GitHub Actions and uploaded directly.** No runtime,
  and simplest at request time. But new storms wait hours for a page, which fails #88, and every
  rebuild regenerates the whole archive (20,000 files per version cap). Whether direct uploads count
  toward the Pages build cap is not documented.
- **Pages generated by the pipeline.** Already rejected in ADR 0002: we would rebuild templating,
  sitemaps and Open Graph tags outside Astro, with a second rendering stack to keep consistent.

## Decision
Deploy `web/` as one Cloudflare Worker with static assets through `@astrojs/cloudflare`. Every page
is prerendered except `/storms/[slug]`, `/storms` (paginated index), `/live/[country]` and the
dynamic sitemap. Those render on demand from JSON read through an R2 binding on `scintille-live`.
Deploys go through GitHub Actions with Wrangler. We stay on Workers Free and keep Workers Cache off
until traffic or CPU says otherwise.

## Consequences
- **Data contract.** The pipeline publishes `storms/index.json`, `storms/<slug>.json`,
  `regions/index.json` and `regions/<country>.json` to `scintille-live`. Their shape becomes part of
  the data contract. An unknown slug, or a country with no storm, returns a real 404, so there are no
  thin pages (#90).
- **Static assets stay free.** Assets are served before the Worker runs, so only the dynamic routes
  count toward 100k requests/day. Do not use `run_worker_first`: past the limit it turns asset
  requests into 429 errors.
- **CPU budget.** Each dynamic route must render in under 10 ms CPU. Keep templates light, parse one
  small JSON file per request, and do no image work at request time (preview images are made by the
  pipeline). Measure this in #88. If p99 gets close to the limit, or traffic gets close to 100k
  dynamic requests a day, move to Workers Paid (5 USD/month). No code change is needed for that.
- **Caching and invalidation.** Dynamic responses set `Cache-Control` with `stale-while-revalidate`
  and a `Cache-Tag` (`storm:<slug>`, `region:<cc>`, `storms-index`). They are stored with the
  Workers Cache API (`caches.default`), which stays free but is per data center. TTLs are short while
  a storm is active (about 5 min) and long once it is closed (1 day or more). An update to a closed
  storm is rare. The pipeline then purges its tag through the zone purge API (allowed on Free, 5
  requests/min). Astro's `cacheCloudflare()` provider and Workers Cache stay off for now: they would
  bill every static asset request against the free quota. Revisit both on Workers Paid, or once the
  provider is stable.
- **Sitemap (#86).** A sitemap index points to the static pages' sitemap, built at build time, and
  to an on-demand `sitemap-storms.xml` and `sitemap-regions.xml` generated from the two index files.
  They are cached like the pages, and paginated past 50,000 URLs.
- **Deployment (#16).** Production deploys on push to `main` after checks pass
  (`wrangler deploy`). Each PR gets `wrangler versions upload --preview-alias pr-<n>`, giving
  `pr-<n>-<worker>.<subdomain>.workers.dev`, and a PR comment with the URL. Previews bind the production
  `scintille-live` bucket. That is safe because the site code only ever reads from it.
  `scintille.app` is attached as a Worker custom domain in `wrangler.jsonc`. HSTS and the `www`
  redirect are zone settings. No Cloudflare Pages project.
- **Terraform (#18).** Terraform owns DNS, both R2 buckets, CORS (allowing `scintille.app` and the
  `*.workers.dev` preview origin), the `www` → apex redirect rule and zone settings (Always Use
  HTTPS, HSTS). Wrangler owns the Worker script, its version history, its custom domain and its R2
  binding, so the two tools never manage the same resource.
- **Tokens (#17).** The GitHub Actions Cloudflare token needs Workers Scripts edit and the zone's
  Workers routes/custom domain permissions. Pages permissions are not needed. The pipeline needs a
  separate token limited to cache purge on the zone.
- **Dev.** `astro dev` runs on `workerd` with the adapter, so local storm pages need a local R2
  binding seeded with fixture JSON.

## Sources
- https://developers.cloudflare.com/pages/: "Start new projects with Workers"; Workers is
  "Cloudflare's primary platform".
- https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/:
  Pages vs Workers feature matrix (Workers lacks some branch deploy controls and custom branch
  aliases; it has better observability, cron, gradual deployments).
- https://developers.cloudflare.com/workers/platform/limits/: Free plan 100,000 requests/day, 10 ms
  CPU per HTTP request, 50 subrequests, 20,000 asset files per version, 25 MiB per file.
- https://developers.cloudflare.com/workers/platform/pricing/: Paid plan from 5 USD/month with
  10 million requests and 30 million CPU ms; past free limits, operations fail with an error.
- https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/: requests to
  static assets are free and unlimited; with `run_worker_first`, matching requests return 429 once
  the free limit is exceeded.
- https://developers.cloudflare.com/pages/platform/limits/: Pages Free 500 builds/month, 1
  concurrent build, 20,000 files; Functions requests count toward the Workers quota.
- https://developers.cloudflare.com/pages/get-started/direct-upload/: Wrangler direct upload is
  limited to 20,000 files of 25 MiB; a direct upload project cannot switch to Git integration; no
  mention of the build cap.
- https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/: Workers Builds Free
  3,000 build minutes/month, 1 concurrent build, 20 min timeout.
- https://developers.cloudflare.com/workers/configuration/previews/: version URLs
  `<alias>-<worker>.<subdomain>.workers.dev` through `wrangler versions upload --preview-alias`;
  only on `workers.dev`; the last 1,000 aliases are kept.
- https://developers.cloudflare.com/workers/previews/: newer per-branch Previews (`wrangler
  preview`), 100 per Worker on Free.
- https://developers.cloudflare.com/workers/runtime-apis/bindings/: R2 bucket binding declared
  with `r2_buckets`.
- https://developers.cloudflare.com/workers/runtime-apis/cache/: `caches.default` stores responses
  per data center, honors `Cache-Control` and `Cache-Tag`; separate from Workers Cache.
- https://developers.cloudflare.com/workers/cache/: Workers Cache serves cached responses without
  running the Worker. Once enabled, every request, including static assets, is billed as a Worker
  request.
- https://developers.cloudflare.com/cache/how-to/purge-cache/: purge by URL, tag, prefix and
  hostname available on Free; 5 requests/min for tag/prefix/hostname purges.
- https://developers.cloudflare.com/r2/pricing/: R2 free tier 10 GB-month, 1M Class A and 10M
  Class B operations per month, free egress.
- https://docs.astro.build/en/guides/integrations-guide/cloudflare/: the adapter supports Workers
  only (Pages dropped in Astro 6, adapter v13+). It enables `prerender = false` per route, and
  bindings come from `cloudflare:workers`.
- https://docs.astro.build/en/guides/on-demand-rendering/: the site stays prerendered by default;
  on-demand pages can return a 404 status.
- https://docs.astro.build/en/guides/caching/: route caching is stable in Astro 7. `cacheCloudflare()`
  sets `Cloudflare-CDN-Cache-Control` and `Cache-Tag`, enables Workers Cache, and supports tag and
  path invalidation; adapter cache providers are still experimental.
